project-evolution 是一个适用于网站、App、Skill、自动化工具和其他软件项目的证据驱动持续进化 Skill：从项目真实目的和用户任务出发，找到值得改进的差距，研究成熟参考，提出可验证的改变，再把结果带回下一轮。

Not limited to one kind of software

项目是什么不重要，
它要为谁解决什么问题才重要。

Skill 会先识别项目类型和环境，但不会把缺少某个框架、服务器或登录功能当成阻塞条件。真正决定进化方向的是项目目的、目标用户和真实任务。

网站 / Web App流程、转化、管理后台、内容体验
移动 App首次使用、核心任务、留存与反馈
Skill / 提示词输入、判断、输出与长期复用
自动化工具任务可靠性、失败恢复、人工节点
其他项目先建立画像，再决定该看什么
The bounded loop

不是“大而全地审查”，
而是一轮一轮解决最值得解决的问题。

每轮只保留一个主焦点。证据不足就停在待验证，方向冲突就交给用户决定，改动完成后沿用同一任务和同一指标复核。

01 / CONTEXT

读懂项目

识别类型、环境、目的、用户和任务入口。

02 / MAP

画出功能地图

区分存在、可用、好用、成熟和未验证。

03 / RESEARCH

定向调研

只研究当前差距需要的规范、案例和成熟产品。

04 / HYPOTHESIS

提出改变

写清基线、目标、风险、验收条件和回退方式。

05 / DECISION

用户做决定

接受、暂缓、拒绝或要求更多证据。

06 / VERIFY

带结果回来

复用原标准，判断支持、失败、不确定或重开。

What gets better

进化不只等于修 Bug。

代码安全和逻辑可靠性是底线，但不是全部。Skill 会把项目是否更好用、更有价值、更接近目标放在同一张判断表里。

项目目的与价值WHY

功能是否真的服务设计目的，而不是越做越偏。

真实用户任务JOB

用户能否顺利完成重要任务，完成后是否愿意继续使用。

体验与交互UX

是否卡住、绕路、误解、放弃，完成不等于好用。

功能成熟度PRODUCT

功能是否完整、严谨、可解释，并有成熟案例可对比。

可靠性与安全TRUST

错误、数据、权限、恢复和边界是否可控。

学习与复用LEARN

有效经验是否留下来，能否让下一轮更准确、更少返工。

Evidence over confidence

每个结论都要知道，
自己凭什么成立。

静态扫描可以帮助定位线索，自动化测试可以证明某个条件通过，但它们不能冒充真实用户体验。证据等级会直接限制报告的语气。

一条可追溯记录链

这些不是宣传标签，而是下一轮可以继续读取的真实记录。

ProjectProfile项目类型、技术栈、运行环境和能力边界
FeatureMap功能入口、用户任务、成熟度和已知差距

# 本轮报告摘要

已验证：项目存在核心任务入口
待验证：用户能否快速完成任务
待验证：结果质量是否达到目的

主焦点：提高核心任务的完成质量
证据门槛：L0 静态线索，不宣称体验改善
用户决定：接受 / 暂缓 / 拒绝 / 要更多证据

下一轮：复用同一任务和指标进行复核
Clear boundaries

自动化负责准备证据，
产品主权仍然在你手里。

它会做什么

  • 读取项目上下文、页面线索和已落盘记录
  • 围绕当前差距整理研究与成熟参考
  • 输出用户看得懂的 Markdown 报告
  • 记录决定、基线和后续验证入口

它不会擅自做什么

  • 不会自动修改业务代码或部署
  • 不会把测试通过说成真实体验通过
  • 不会把历史任务冒充成当前需求
  • 不会替用户决定产品方向或升级通用规则
Start with one project

先指定一个项目，
从最小闭环开始。

第一次使用先建立项目画像和功能线索。后续每一轮只需要查看报告，决定是否接受某个改进方向。

你会得到什么

一个面向小白的 `latest-report.md`，加上一组可追溯的结构化记录。没有当前任务时，Skill 会明确停在历史基线或待确认状态，不硬凑结论。
